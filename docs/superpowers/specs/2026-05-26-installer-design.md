# Phase 12 — Installer + Deployment

## Concept & Vision

A cross-platform CLI wizard (`moka install`) that gives users a single command to go from blank machine to fully-running MokaAI. Scan hardware → show model recommendations → install deps → write config → register service. Two layers: `installer.core` (business logic, no UI) + `installer.cli` (rich TTY wizard). Follows the same separation MokaAI uses between core services and presentation.

---

## Architecture

### Two-Layer Design

**`installer.core`** — Pure business logic. Importable programmatically. No side effects except config file writes.
**`installer.cli`** — Rich TTY wizard. Calls `installer.core`. Handles all user interaction.

```
installer/
├── __init__.py
├── core.py              # ScanRecommendInstallConfigure service API
│   ├── HardwareScan     # wraps HardwareScanner + extends for installer context
│   ├── SoftwareDetector # CUDA, Python version, existing packages
│   ├── ModelRecommender # tiered recommendations from tiers.yaml
│   ├── DepResolver     # computes required pip/system packages
│   ├── ConfigWriter    # generates config.yaml from template
│   └── ServiceManager  # register/unregister OS-native services
├── cli.py               # rich TTY wizard
├── data/
│   └── tiers.yaml       # model tier definitions
└── templates/
    └── config.yaml.j2  # config template

tests/
└── test_installer.py
```

## Hardware Scan

Steps on launch:

1. Call `HardwareScanner().scan()` — returns `HardwareProfile(gpu_model, vram_gb, system_ram_gb, available_vram_gb, compute_capability)`
2. Display machine summary in a rich `Table` — "24GB VRAM · 64GB RAM · NVIDIA RTX 4090"
3. Run `SoftwareDetector` — checks Python version, NVIDIA driver (`nvidia-smi`), CUDA version
4. Show any warnings: "Python 3.9 required, found 3.11 ✓", "CUDA 12.4 found ✓"

Display format: rich colored table, hardware friendly (no raw jargon).

## Model Recommendations

Based on VRAM tier from `tiers.yaml`, preselect models. User can accept or change.

### Default Tier Mapping

| VRAM | Base Model | Image Model | Voice Model |
|------|-----------|-------------|-------------|
| 4GB | llama3.2 1B | sd-turbo (CPU) | silero-tiny |
| 8GB | llama3.2 3B | sd-turbo | silero-small |
| 12GB | mistral 7B | sd-xl-lite | silero-small |
| 16GB | deepseek-coder 7B | sd-xl | silero-medium |
| 24GB+ | deepseek-coder 33B | sd-xl-high | silero-medium |

`tiers.yaml` defines all models with: `name`, `size_gb`, `min_vram_gb`, `type` (base|image|voice), `url` (HuggingFace), `hf_id`.

Wizard shows `Table` with recommended models, their download sizes, and VRAM requirements. User presses Enter to accept or `N` to pick from list.

## Storage Estimate

After model selection:
- Sum `size_gb` for all selected models
- Check `psutil.disk_usage(moka_base_path)` for free space
- Display: "Selected models: 8.2GB | Free space: 450GB ✓"
- If insufficient: warn and suggest smaller models

## Dependency Resolution

`DepResolver.resolve(selected_models, hardware_profile)` returns a list of packages to install:

- Core: `flask flask-socketio eventlet psutil requests pyyaml`
- Voice: `speechrecognition pyttsx3 pyaudio sounddevice`
- Image: `torch transformers diffusers sentencepiece`
- Installer itself: `rich` (for TTY), `click` (CLI framework)

Show in `rich Progress` table with columns: `Package`, `Action` (install/upgrade/skip), `Status`.

Run via `subprocess.Popen([sys.executable, "-m", "pip", "install", ...], ...)` to use the Python that will run Moka.

## Config Generation

`ConfigWriter.write(config_path, selected_models, hardware_profile)` renders `config.yaml.j2` with:

```yaml
# Config for MokaAI — generated by installer
moka_dir: ~/.moka/
models_dir: ~/.moka/models/
logs_dir: ~/.moka/logs/

# Hardware-tuned limits
hardware:
  gpu: "{{ gpu_model }}"
  vram_gb: {{ vram_gb }}
  compute_capability: "{{ compute_capability }}"

limits:
  max_resolution: {{ max_resolution_from_tier }}
  max_steps: {{ max_steps_from_tier }}
  max_concurrent: {{ max_concurrent_from_tier }}

models:
  base: {{ base_model_hf_id }}
  image: {{ image_model_hf_id }}
  voice: {{ voice_model_hf_id }}

voice:
  wake_word: "Hey Moka"
  tts_voice: "default"
```

Write to `~/.moka/config/config.yaml` (expand `~` to home dir).

## Service Registration

### Option A: Python-level (cross-platform, always available)

`ServiceManager.start()` — runs `moka run` in a daemonized subprocess (background process, persistent across terminal sessions). Uses `nohup` on Unix, similar on Windows.

### Option B: OS-native (optional, more integrated)

**Linux (systemd):**
```
~/.config/systemd/user/moka-ai.service
→ systemctl --user enable moka-ai
→ systemctl --user start moka-ai
```

**macOS (launchd):**
```
~/Library/LaunchAgents/com.moka-ai.plist
→ launchctl load ~/Library/LaunchAgents/com.moka-ai.plist
```

**Windows (NSSM):**
```
nssm install MokaAI "C:\path\to\python.exe" "C:\path\to\moka\run"
```

Ask user: "Register as system service?" (y/N). Default no. Offer both "Install service" and "Just run Moka for now".

## CLI Interface

```
# Full installation wizard
moka install

# Selective options
moka install --skip-hw      # Skip hardware scan, use cached profile
moka install --minimal       # Defaults only, no prompts

# Service management
moka service install        # Register service (uses OS-native if available)
moka service uninstall      # Remove service
moka service status         # Check running state
moka service start          # Start service
moka service stop           # Stop service

# Direct commands
moka run                    # Run MokaAI directly
moka config                 # Open config in editor
moka logs                   # Stream recent logs
moka doctor                 # Run diagnosis (hardware + deps + config)
```

## Error Handling

| Scenario | Behavior |
|----------|---------|
| nvidia-smi not found | Warn: "No NVIDIA GPU detected. Image generation will use CPU." Continue wizard. |
| CUDA version mismatch | Warn with required vs found version. Offer to install matching PyTorch. |
| Disk space insufficient | Block proceed until user picks smaller models or changes install path. |
| Network failure during dep install | Retry 2x, then fail with "Check internet connection" + URL to install manually. |
| Service registration fails | Warn but don't block. Offer manual instructions for each platform. |
| Config already exists | Ask: "Config exists at ~/.moka/config.yaml. Overwrite?" (default backup old one). |
